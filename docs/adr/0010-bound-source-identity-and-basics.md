# ADR-0010 — Bind source subjects before relevance; select basics with a minimal projection

Status: source-bound identity projection implemented and deployed for the synthetic demo; presenter aliases are separate from source identity.

A modelled encounter must bind an explicit source-person key on **every** new demo record before `policy.cut`; missing/mismatched record ownership, a duplicated record ID, or a source-person key mapped to multiple people rejects the whole encounter with the same public error as unknown context. Do not derive ownership from a name, a note's wording or the containing persona. The owner chose to permit `record_type == "perustieto"` with topic `demografia` through the ordinary purpose policy *after* role, consent and sensitivity checks, so the deterministic baseline selects it. This is not a broad `demografia` topic exception for arbitrary record types. It deliberately changes selected IDs, so historical frozen results remain unchanged; the selection-contract version itself is owned by [ADR-0009](0009-decision-purpose-relevance-selection.md) and is not restated here, because a version number goes stale on the next contract change while this ownership rule does not.

For the identity view, project only `nimi` and the **synthetic** `näyttötunniste`; send neither field to Foundry narration nor to the Decision-1 grounding verifier. Use one shared basics-projection seam for the Picture and both model stages, never passing unlisted source-payload fields. A validly bound encounter with zero **permitted** basics shows a neutral “Henkilöllisyystieto ei saatavilla” header without hinting whether any source was excluded. More than one basics record for that person rejects the encounter as ambiguous. **Local implementation:** four source-keyed historical bound encounter routes exist; persona-003's single derived copy is shared by its two nurse contexts. `bound-source-002/003/004` are manually assigned synthetic identifiers for derived demo copies only—not original provenance, clinical/50k evidence. These copies have no approved source display name/ID and use neutral source identity. Revision `luvn-challenge11-product--0000009` additionally supplies explicitly labelled synthetic presenter aliases in the encounter index; the aliases are not added to source records, do not participate in person binding, and do not go to the models. The v2 fixture is exercised only with mocked offline tests; its two runtime IDs return 404 pending human label adjudication and separate live-call authorization. Original persona-003/004 files were already dirty and were not changed by this work. The bound-source checks are deployed in the synthetic demo, not validated for real sources. No real 50,000-profile identity safety claim follows.
